# HTTP API

Everything the UI and the chat channels can do is available under `/api/v1`. The OpenAPI 3.1 spec is
generated by huma: `GET /api/v1/openapi.json` (`/openapi.json` redirects), interactive docs at `/api/v1/docs`.
`infra-monitor openapi` prints the spec offline (used to generate the UI's TypeScript client).

## Authentication

| Method | How |
| --- | --- |
| Browser session | Cookie `im_session` (httpOnly, SameSite=Lax, Secure on https). State-changing requests (POST/PUT/PATCH/DELETE) must also send `X-CSRF-Token: <csrf_token from GET /me>`. |
| API token | `Authorization: Bearer imt_...` (create with `infra-monitor token create` or `POST /tokens`). No CSRF needed. |
| Source webhooks | Per-source bearer token or basic auth (see `sources[].auth` in the config). |

Roles: `viewer` (read), `operator` (chat, ack, resolve, mute, approve/reject, propose actions), `admin` (users, tokens).
Errors use RFC 7807 problem JSON: `{"title","status","detail","errors"?}`. 401 means not logged in, 403 means role too low.

Timestamps are RFC 3339 strings. IDs are integers.

## Objects

```ts
Incident {
  id, title, status: "open"|"acknowledged"|"resolved"|"closed", severity, cluster, namespace, source,
  verdict: "actionable"|"noise"|"unknown", summary, muted, internal, labels: Record<string,string>,
  opened_at, acknowledged_at?, resolved_at?, last_signal_at, duration_seconds,
  signal_count, firing_count, pending_actions, reopen_count,
  investigation_state: "none"|"pending"|"running"|"done"|"failed"|"skipped",
  notify_channels: string[], assignee?: {id, name}, trace_id, url
}
Signal { id, source, fingerprint, status: "firing"|"resolved", name, severity, cluster, namespace, labels, annotations,
         starts_at, ends_at?, generator_url, last_seen_at, fire_count }
Investigation { id, status: "pending"|"running"|"succeeded"|"failed"|"timed_out", trigger: "auto"|"manual"|"action",
                agent, model, analysis, summary, root_cause, verdict, confidence, tool_calls: any[], error,
                prompt_tokens, completion_tokens, created_at, started_at?, finished_at?, trace_id }
Message { id, incident_id, role: "user"|"agent"|"system", author_name, channel, channel_name, content, status: "done"|"pending"|"failed",
          action_ids: number[], created_at }
Action { id, incident_id, type, params, rationale, risk: "low"|"medium"|"high", proposed_by: "agent"|"user"|"system",
         status: "proposed"|"approved"|"rejected"|"running"|"succeeded"|"failed"|"expired", summary,
         decided_by_name, decided_via, decided_at?, expires_at, started_at?, finished_at?, output, error, created_at }
TimelineEvent { id, incident_id, type, actor_type: "user"|"agent"|"system", actor_name, channel, channel_name, payload, trace_id, created_at }
Mute { id, matchers: [{name, op: "="|"!="|"=~"|"!~", value}], starts_at, ends_at, reason, created_by_name, active,
       incident_id?, alertmanager_silence_id }
ActionType { type, description, risk, params_schema, auto_approve }
User { id, email, display_name, role, disabled, auth: ("local"|"oidc")[], last_login_at?, created_at }
APIToken { id, name, prefix, role, user_id?, last_used_at?, expires_at?, revoked_at?, created_at }
```

Timeline event types: `incident_opened`, `incident_reopened`, `signal_firing`, `signal_resolved`, `incident_status_changed`
(payload `{from,to,reason}`), `investigation_started|completed|failed|skipped`, `action_proposed|approved|rejected|started|succeeded|failed|expired`
(payload `{action_id, type, summary, ...}`), `message` (payload `{message_id, role, content}`), `mute_created|mute_ended`,
`notification_routed` (payload `{channels}`), `notification_sent`, `assigned`, `agent_thinking`.

## Endpoints

| Method & path | Role | Notes |
| --- | --- | --- |
| `GET /auth/config` | public | `{local_enabled, oidc_enabled, oidc_name}` |
| `POST /auth/login` | public | `{email, password}` → `Me`, sets the session cookie |
| `POST /auth/logout` | viewer | clears the session |
| `GET /auth/oidc/login?redirect=/path` | public | 302 to the provider (PKCE) |
| `GET /auth/oidc/callback` | public | 302 back to `redirect` with a session |
| `GET /me` | viewer | `Me {id, email, display_name, role, auth_method, csrf_token, identities: [{channel_type, external_name}], trace_url_template}` |
| `POST /me/link-code` | viewer | `{code, expires_at, instructions}`; send `/link CODE` to the bot |
| `DELETE /me/identities/{channel_type}` | viewer | unlink |
| `GET /incidents` | viewer | filters: `status` (csv), `severity` (csv), `cluster`, `namespace`, `verdict` (csv), `q` (text), `since`, `until`, `muted`, `limit` (≤200, default 50), `cursor` → `{items: Incident[], next_cursor?, total}` |
| `GET /incidents/histogram` | viewer | same filters + `buckets` (default 60) → `{buckets: [{start, end, critical, warning, info, other}]}` |
| `GET /incidents/{id}` | viewer | `Incident` + `latest_investigation?` |
| `GET /incidents/{id}/timeline` | viewer | `after_id` → `{items: TimelineEvent[]}` (ascending) |
| `GET /incidents/{id}/signals` | viewer | `{items: Signal[]}` |
| `GET /incidents/{id}/investigations` | viewer | `{items: Investigation[]}` (newest first) |
| `GET /incidents/{id}/messages` | viewer | `{items: Message[]}` (ascending) |
| `POST /incidents/{id}/messages` | operator | `{content}` → `Message`; the agent reply arrives asynchronously |
| `GET /incidents/{id}/actions` | viewer | `{items: Action[]}` |
| `POST /incidents/{id}/actions` | operator | `{type, params, rationale?}` → `Action` (user proposal; still needs approval) |
| `POST /incidents/{id}/ack` | operator | → `Incident` |
| `POST /incidents/{id}/resolve` | operator | `{reason?}` → `Incident` |
| `POST /incidents/{id}/reopen` | operator | → `Incident` |
| `POST /incidents/{id}/reinvestigate` | operator | → `Incident` |
| `POST /incidents/{id}/mute` | operator | `{duration: "1h", reason?}` → `Mute` (matches the incident's grouping labels) |
| `POST /actions/{id}/approve` | operator | → `Action` |
| `POST /actions/{id}/reject` | operator | `{reason?}` → `Action` |
| `GET /action-types` | viewer | `{items: ActionType[]}` |
| `GET /mutes` | viewer | `active` (bool) → `{items: Mute[]}` |
| `POST /mutes` | operator | `{matchers, duration? | ends_at?, starts_at?, reason, mirror_to_alertmanager?, source?}` → `Mute` |
| `DELETE /mutes/{id}` | operator | expires the mute now |
| `GET /status` | viewer | `{version, replica, sources: [...], channels: [...], heartbeats: [...], agent: {...}, leases: [...]}` |
| `GET /users` | admin | `{items: User[]}` |
| `POST /users` | admin | `{email, display_name?, role, password?}` → `User` |
| `PATCH /users/{id}` | admin | `{role?, disabled?, display_name?, password?}` → `User` |
| `GET /tokens` | admin | `{items: APIToken[]}` |
| `POST /tokens` | admin | `{name, role, expires_in?: "720h"}` → `APIToken & {token}` (shown once) |
| `DELETE /tokens/{id}` | admin | revoke |
| `POST /sources/{name}/webhook` | source auth | Alertmanager webhook payload (v4); returns 202 fast, processing is async |
| `POST /channels/{name}/webhook` | channel secret | Telegram webhook mode (`X-Telegram-Bot-Api-Secret-Token`) |
| `GET /events` | viewer | Server-Sent Events, see below |

## Live updates (SSE)

`GET /api/v1/events[?incident_id=42]` streams:

- `event: timeline` — `data: {"id":123,"incident_id":42,"type":"action_proposed"}` for every timeline insert (all replicas, via
  Postgres LISTEN/NOTIFY). Clients refetch what they display.
- `event: progress` — `data: {"incident_id":42,"kind":"tool_call"|"tool_result"|"message"|"done","tool":"kubectl_logs","text":"..."}`
  while the agent investigates or answers (ephemeral, not stored).
- `event: resync` — the server lost its database listener and reconnected; refetch everything.
- `event: ping` every 25s.
